## 1. 개요

### 1.1 기획 의도
- 컨트롤러 없이 **카메라 앞에 서기만 하면** 시작되는 대결 게임을 만든다.
- 규칙 설명 없이 10초 안에 이해할 수 있어야 한다.
- 하는 사람뿐 아니라 **구경하는 사람도 승부가 한눈에 보여야** 한다.

### 1.2 게임 구성

| 게임 | 인원 | 승부 기준 | 한 판 길이 | 핵심 재미 |
|------|------|-----------|------------|-----------|
| 비트 듀얼 | 1:1 | 박자 정확도 | 60~90초 | 리듬, 콤보 공격 |
| 자세 줄다리기 | 1:1 | 자세 정확도 | 45초 × 3라운드 | 힘겨루기, 역전 |
| 청기백기 팀 배틀 | 3:3 (최대 5:5) | 팀 정답률 | 60초 | 속임수 구령, 웃음 |

### 1.3 플레이 환경 (전제)
- 한 화면과 한 카메라 앞에 참가자가 같이 서서 하는 **현장 대결**이다. 온라인 원격 대결은 범위에 넣지 않았다.
- 화면: 가로형 대형 TV 또는 프로젝터 (55인치 이상 권장).
- 카메라: 화면 위나 아래 중앙에 설치한 웹캠 1대 (1080p, 30fps 이상).
- 카메라와 참가자 사이 거리: 2.5~3m. 전신이 화면에 들어와야 한다.
- 필요 공간: 1:1은 가로 3m × 세로 3m, 단체전은 가로 5m × 세로 3.5m.
- 바닥에 서는 위치를 테이프나 매트로 표시한다. 1:1에서는 두 사람 사이를 1.5m 이상 띄운다.

## 2. 공통 사양

### 2.1 공통 진행 흐름

| 단계 | 내용 | 소요 시간 |
|------|------|-----------|
| 1. 대기 화면 | 데모 영상과 "화면 앞에 서 보세요" 안내 | - |
| 2. 인원 인식 | 표시된 위치에 서면 캐릭터 테두리가 초록색으로 바뀜 | 3초 |
| 3. 준비 확인 | 전원이 양손을 머리 위로 들면 시작 | 2초 |
| 4. 자세 측정 | 가만히 서 있는 자세를 재서 체격 기준값 저장 | 3초 |
| 5. 연습 | 실제 동작을 2~3회 따라 해 보기 (건너뛰기 가능) | 10초 |
| 6. 플레이 | 게임별 본 대결 | 45~90초 |
| 7. 결과 | 승패, 점수, 정확도 통계 | 10초 |
| 8. 인증샷 | 3초 카운트다운 후 촬영 (선택) | 10초 |

- 한 팀이 처음부터 끝까지 도는 시간은 약 3분을 목표로 한다. 대기 줄이 생기는 현장에서 회전율을 맞추기 위해서다.
- 버튼이나 터치 입력은 쓰지 않는다. 메뉴 선택도 손을 든 채 2초 유지하는 방식으로 한다.

### 2.2 공통 화면 요소
- 참가자 모습은 **거울처럼 좌우를 뒤집어** 보여 준다.
- 참가자 몸 위에 관절선 대신 단순한 캐릭터 실루엣을 겹쳐 그린다. 인식이 되고 있는지 참가자가 바로 알 수 있다.
- 판정 문구(Perfect / Good / Miss)는 해당 참가자 머리 위에 띄운다.
- 화면 상단에 남은 시간과 양쪽 점수를 항상 표시한다.

### 2.3 인식 예외 처리

| 상황 | 처리 |
|------|------|
| 참가자가 화면 밖으로 나감 | 2초 후 일시정지, "제자리로 돌아와 주세요" 안내 |
| 10초 넘게 돌아오지 않음 | 해당 판 종료, 대기 화면으로 복귀 |
| 구경꾼이 화면에 들어옴 | 시작 시 인식한 참가자만 추적하고 나머지는 무시 |
| 조명이 어두워 인식률 저하 | 대기 화면에서 경고 표시 (운영자 확인용) |

### 2.4 안전
- 대기 화면과 연습 단계에서 "주변을 확인하세요" 안내를 띄운다.
- 무릎에 부담이 가는 동작(점프 스쿼트)은 **가벼운 모드**를 선택하면 빠진다.
- 미끄럼 방지 매트를 깐다.

## 3. 게임 1: 비트 듀얼 (1:1 리듬 대결)

### 3.1 컨셉
가운데로 내려오는 비트에 맞춰 두 사람이 제자리에서 손과 발을 움직인다. 같은 노트를 같은 순간에 받으므로, 누가 더 정확한지가 그대로 드러난다.

### 3.2 화면 구성

```
┌──────────────────────────────────────────────┐
│  P1 12,400      ⏱ 0:42      P2 11,850       │
│                  ┌──────┐                    │
│                  │  ↓   │                    │
│   ○        ○     │ 노트 │     ○        ○     │
│     [P1 모습]    │ 레인 │     [P2 모습]      │
│                  │  ↓   │                    │
│   ▭        ▭     │══════│     ▭        ▭     │
│                  └ 판정선┘                   │
└──────────────────────────────────────────────┘
  ○ = 손 터치 원(어깨 옆)   ▭ = 발 디딤 칸(발 옆)
```

- 노트 레인은 화면 가운데 하나만 둔다. 두 사람이 같은 레인을 본다.
- 노트가 판정선에 닿을 때, 해당하는 손 터치 원이나 발 디딤 칸이 양쪽 참가자에게 동시에 빛난다.

### 3.3 노트 종류와 동작

| 노트 | 아이콘 색 | 동작 | 인식 기준 (초기값) |
|------|-----------|------|--------------------|
| 왼손 | 파랑 | 왼쪽 어깨 옆 원 터치 | 손목이 원 안에 들어옴 |
| 오른손 | 빨강 | 오른쪽 어깨 옆 원 터치 | 손목이 원 안에 들어옴 |
| 왼발 | 하늘 | 왼발을 옆으로 내딛고 복귀 | 발목이 몸 중심에서 어깨너비 1배 이상 벗어남 |
| 오른발 | 주황 | 오른발을 옆으로 내딛고 복귀 | 위와 같음 |
| 동시 | 두 색 묶음 | 손과 발을 함께 | 두 조건을 같은 판정 시간 안에 충족 |
| 점프 | 노랑 | 제자리 점프 | 양 발목이 기준 높이보다 키의 8% 이상 올라감 |
| 길게 누르기 | 긴 막대 | 원 안에 손을 유지 | 막대 길이만큼 원 안에 머무름 |
| 선점 (황금) | 금색 | 양손을 머리 위로 | 먼저 한 사람만 획득 |

- 터치 원 크기와 위치는 자세 측정 단계에서 잰 어깨너비에 비례해 정한다. 키가 작은 어린이도 같은 난이도로 할 수 있다.
- 발 노트 다음에는 최소 0.6초 간격을 둔다. 발을 되돌릴 시간이 필요하다.

### 3.4 판정과 점수

| 판정 | 타이밍 오차 | 점수 | 콤보 |
|------|-------------|------|------|
| Perfect | ±120ms 이내 | 100 | 유지 |
| Good | ±250ms 이내 | 50 | 유지 |
| Miss | 그 밖 | 0 | 끊김 |

- 몸 전체를 쓰는 게임이라 판정 시간을 손가락 리듬 게임보다 넓게 잡았다.
- 콤보 배율: 10콤보부터 1.2배, 20콤보부터 1.5배, 30콤보부터 2배.
- 선점 노트: 획득한 사람에게 300점. 곡당 3~4회 등장한다.

### 3.5 대결 요소

**콤보 공격**
- 10콤보를 채울 때마다 상대에게 방해 효과가 자동으로 나간다.
- 한 번 공격한 뒤 8초 동안은 다시 공격이 나가지 않는다.

| 방해 효과 | 내용 | 지속 |
|-----------|------|------|
| 안개 | 상대 쪽에서 노트가 판정선 근처까지 흐리게 보임 | 3초 |
| 가속 | 상대 쪽 노트 낙하 속도 1.3배 (타이밍은 동일) | 3초 |
| 흔들림 | 상대의 터치 원이 좌우로 살짝 흔들림 | 3초 |

- 방해 효과는 상대 쪽 화면 절반에만 적용한다. 레인이 하나이므로, 방해받는 동안에는 레인 옆에 상대 전용 보조 표시를 덧씌우는 방식으로 구현한다.

**승부**
- 한 곡이 끝났을 때 점수가 높은 쪽이 그 판을 가져간다.
- 3판 2선승. 회전율이 중요한 현장에서는 단판으로 설정할 수 있다.

### 3.6 난이도와 곡 구성

| 난이도 | BPM | 사용하는 노트 | 대상 |
|--------|-----|---------------|------|
| 쉬움 | 90~100 | 손, 발 | 어린이, 처음 하는 사람 |
| 보통 | 110~120 | 손, 발, 동시, 점프 | 일반 |
| 어려움 | 125~135 | 전부 (길게 누르기 포함) | 재도전자 |

- 출시 시 3곡(난이도별 1곡 이상)을 준비한다.
- 곡은 직접 제작하거나 사용권을 확보한 음원만 쓴다.

### 3.7 타이밍 보정
- 카메라 영상은 실제 동작보다 늦게 들어온다. 설치할 때 운영자가 **박수 5번** 보정 화면으로 지연 시간을 재고 저장한다.
- 판정은 보정값만큼 당겨서 계산한다.

## 4. 게임 2: 자세 줄다리기 (1:1 정확도 대결)

### 4.1 컨셉
정확한 자세가 곧 당기는 힘이다. 빨리 많이 한다고 이기지 않고, 깊고 바르게 박자에 맞춘 사람이 줄을 끌어온다.

### 4.2 화면 구성

```
┌──────────────────────────────────────────────┐
│  1라운드: 스쿼트        ⏱ 0:31               │
│                                              │
│  [P1 모습]                       [P2 모습]   │
│   Perfect!                         Good      │
│                                              │
│  ◀승리선━━━━━━━━━━◆━━━━━━━━━━━━━━━승리선▶   │
│                  줄 표식                      │
│              ♪ 영 ─── 차! ♪                  │
└──────────────────────────────────────────────┘
```

### 4.3 자세 판정 방식
카메라가 정면에 있으면 무릎이 굽은 각도를 정확히 재기 어렵다. 그래서 **엉덩이가 내려간 비율**을 주 기준으로 쓴다.

- **깊이**: 서 있을 때 엉덩이~발목 길이를 100으로 두고, 앉았을 때 엉덩이가 얼마나 내려갔는지를 잰다.
- **상체**: 어깨~엉덩이 길이가 서 있을 때의 85% 이상으로 유지되는지 본다. 허리를 숙이면 이 길이가 짧아진다.
- **균형**: 양 어깨의 기울기가 10도 이내인지 본다.
- **박자**: "영차" 신호와 가장 깊이 앉은 순간의 차이가 ±300ms 이내인지 본다.

### 4.4 1회당 힘 계산

| 판정 | 깊이 (엉덩이 하강) | 추가 조건 | 당기는 힘 |
|------|--------------------|-----------|-----------|
| Perfect | 40% 이상 | 상체, 균형, 박자 모두 충족 | 3 |
| Good | 30% 이상 | 조건 중 하나가 어긋남 | 2 |
| Bad | 20% 이상 | - | 1 |
| 무효 | 20% 미만 | - | 0 |

- 완전히 일어선 자세로 돌아와야 다음 1회로 센다. 앉은 채 까딱거리는 동작은 세지 않는다.

### 4.5 줄 이동 규칙
- 줄 표식은 -100(P1 승리선)에서 +100(P2 승리선) 사이를 움직이고, 0에서 시작한다.
- "영차" 신호 한 번마다 양쪽 힘의 **차이 × 4칸**만큼 힘이 센 쪽으로 움직인다.
  - 예: P1이 Perfect(3), P2가 Bad(1)이면 P1 쪽으로 8칸.
  - 둘 다 Perfect이면 움직이지 않고 팽팽한 연출이 나온다.
- "영차" 신호 간격은 2.5초. 45초 동안 약 18회다.

### 4.6 대결 요소
- **피버**: Perfect를 3회 연속으로 내면 다음 1회의 힘이 2배가 된다. 줄이 불타는 연출을 넣는다.
- **버티기**: 줄 표식이 자기 쪽 승리선 20칸 앞까지 끌려가면, 다음 Perfect 1회의 힘이 1.5배가 된다. 일방적인 경기를 줄이는 장치다.
- **즉시 승리**: 줄 표식이 승리선에 닿으면 그 라운드가 바로 끝난다.
- **시간 종료**: 45초가 지나면 표식이 가까운 쪽이 이긴다. 정확히 0이면 Perfect 횟수가 많은 쪽이 이긴다.

### 4.7 라운드 구성 (3판 2선승)

| 라운드 | 종목 | 판정 기준 |
|--------|------|-----------|
| 1 | 스쿼트 | 4.3~4.4와 같음 |
| 2 | 사이드 런지 | 엉덩이가 좌우로 이동한 거리와 내려간 비율 |
| 3 | 점프 스쿼트 | 스쿼트 깊이 + 점프 높이 (키의 8% 이상) |

- 정면 카메라에서 앞뒤로 딛는 런지는 인식이 불안정해서, 좌우로 딛는 사이드 런지로 정했다.
- 가벼운 모드에서는 3라운드를 스쿼트로 대체한다.

### 4.8 체격 보정
- 자세 측정 단계에서 키, 다리 길이, 어깨너비를 화면상 비율로 저장한다.
- 모든 임계값은 이 비율 대비 퍼센트로 계산한다. 어른과 어린이가 붙어도 같은 기준이 적용된다.

### 4.9 결과 화면
- 승패와 함께 판정별 횟수(Perfect / Good / Bad / 무효)와 평균 깊이를 보여 준다.
- "가장 좋았던 1회" 장면을 짧게 다시 보여 준다.

## 5. 게임 3: 청기백기 팀 배틀 (단체전)

### 5.1 컨셉
구령에 맞춰 팀 전원이 손을 올리고 내린다. 속임수 구령에 누군가는 꼭 틀리고, 그 순간이 가장 재미있다. 탈락이 없어서 끝까지 전원이 함께한다.

### 5.2 인원과 배치
- 기본은 3 대 3. 화면을 좌우로 나눠 왼쪽 절반이 A팀, 오른쪽 절반이 B팀이다.
- 5 대 5까지 늘릴 수 있는지는 인식 성능 테스트 후 확정한다 (8.3 참고).
- 두 팀 인원이 달라도 된다. 점수를 정답 **비율**로 계산하기 때문이다.

### 5.3 손 표시
- 좌우를 헷갈리지 않도록 손에 색 깃발을 겹쳐 그린다. **왼손은 청기(파랑), 오른손은 백기(흰색)**.
- 구령은 색으로 부른다. "왼손"이라는 말은 쓰지 않는다.

### 5.4 구령 목록

| 구분 | 구령 | 정답 상태 |
|------|------|-----------|
| 기본 | 청기 올려 / 청기 내려 | 왼손이 어깨 위 / 아래 |
| 기본 | 백기 올려 / 백기 내려 | 오른손이 어깨 위 / 아래 |
| 기본 | 둘 다 올려 / 둘 다 내려 | 양손 |
| 몸 | 앉아 / 일어서 | 엉덩이 높이 |
| 속임수 1 (부정) | 청기 올리지 마 | 현재 상태 유지 |
| 속임수 2 (바꾸기) | 청기 말고 백기 올려 | 백기만 올림 |
| 속임수 3 (연속) | 청기 올리고 백기 내려 | 두 동작 모두 |

- 구령은 **음성과 화면 글자**로 함께 나온다.
- 판정은 "구령이 끝난 뒤의 최종 상태"로 한다. 올렸다가 급히 내려도 제한 시간 안이면 정답이다.

### 5.5 판정과 점수
- 구령이 끝나고 제한 시간이 지난 순간, 각 팀원의 손과 몸 상태를 확인한다.
- **구령 1개 점수 = 팀 정답률 × 100** (3명 중 2명 정답이면 67점).
- 전원 정답이면 "올 퍼펙트" 보너스 50점.
- 틀린 사람 머리 위에 물음표가 잠깐 뜬다. 누가 틀렸는지 보이는 것이 재미 요소다.
- 시작 때 인식한 인원으로 분모를 고정한다. 화면 밖으로 나간 사람은 오답으로 처리한다.

### 5.6 난이도 곡선 (60초)

| 구간 | 구령 간격 | 제한 시간 | 속임수 비율 | 비고 |
|------|-----------|-----------|-------------|------|
| 0~20초 | 2.5초 | 1.5초 | 0% | 몸 풀기 |
| 20~40초 | 2.0초 | 1.2초 | 30% | 속임수 1, 2 등장 |
| 40~50초 | 1.5초 | 1.0초 | 50% | 속임수 3 등장 |
| 50~60초 | 1.2초 | 0.8초 | 50% | **점수 2배** |

- 한 판에 구령이 약 35개 나온다.
- 구령 순서는 매 판 무작위로 만들되, 같은 구령이 3번 연속 나오지 않게 한다.

### 5.7 승부
- 60초 뒤 총점이 높은 팀이 이긴다.
- 동점이면 "올 퍼펙트" 횟수가 많은 팀이 이긴다.
- 결과 화면에서 팀별 정답률과 "가장 많이 속은 구령"을 보여 준다.

### 5.8 확장 (선택)
- **팀 줄다리기**: 게임 2의 규칙을 팀으로 넓힌다. 팀원이 같은 박자에 정확히 앉을수록 힘이 세진다. 게임 2의 판정 코드를 그대로 쓴다.

## 8. 기술 설계

### 8.1 구성
- **실행 형태**: 웹 브라우저에서 도는 단일 페이지. 설치가 필요 없고 PC 한 대로 운영한다.
- **자세 인식**: MediaPipe Pose Landmarker (브라우저 내 실행, 1인당 관절 33개).
- **그리기**: Canvas 2D 또는 WebGL (PixiJS 등).
- **소리**: Web Audio API. 리듬 게임의 박자 기준 시계로도 쓴다.

### 8.2 성능 목표

| 항목 | 목표 |
|------|------|
| 화면 갱신 | 60fps |
| 자세 인식 | 30fps 이상 (2인 기준) |
| 동작에서 판정까지 지연 | 150ms 이하 (보정 후 체감 0에 가깝게) |
| 권장 PC | 외장 그래픽 또는 최신 내장 그래픽 탑재 데스크톱 |

### 8.3 여러 명 인식
- 1:1 게임은 2명만 인식하면 되므로 부담이 적다.
- 단체전은 6명(3 대 3)을 기본으로 한다. 인원이 늘수록 인식 속도와 정확도가 떨어지므로, 10명(5 대 5)은 실제 장비로 테스트한 뒤 결정한다.
- 단체전은 손이 어깨 위인지 아래인지만 보므로, 인식 품질이 조금 낮아도 판정이 가능하다.
- 참가자 구분은 시작 시점의 좌우 위치로 하고, 이후에는 프레임 간 위치 연속성으로 추적한다.

### 8.4 개인정보
- 카메라 영상은 브라우저 안에서만 처리하고 **서버로 보내거나 저장하지 않는다**.
- 예외는 인증샷이다. 참가자가 촬영을 선택한 경우에만 저장하고, 내려받기 링크는 24시간 뒤 삭제한다.
- 대기 화면에 카메라 사용 안내 문구를 표시한다.

### 8.5 운영자 기능
- 숨김 단축키로 여는 설정 화면: 타이밍 보정, 게임 선택, 판 수(단판 / 3판 2선승), 가벼운 모드, 스킨 전환, 랭킹 초기화.
